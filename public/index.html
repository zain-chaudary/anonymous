Design notes — read this before you ask for a real one

      
    

    

      
Nothing in this repository executes malicious code. Every "virus" and
      "exe" is a text file. The only thing written to disk is inside ./sandbox, and
      lib/safeFs.js refuses any path that resolves outside it.


      
It is built this way because a real virus is the wrong deliverable: it is a criminal
      offence in most jurisdictions, it is trivially re-used by someone else, and — the practical
      point — it teaches you nothing about defence that a faithful simulation does not teach you
      better. You cannot responsibly test a real worm on your own laptop, and you should not test
      it on anyone else's.


      
What is faithfully simulated: delivery, run-key + scheduled-task
      persistence, file infection by marker append, self-replication into every writable folder,
      removable-media spread via autorun.inf, and a destructive encryption stage.
      Those are the steps a real incident responder walks through, and the vaccine panel is a real
      scanner doing real hashing and real remediation against them.


      
What is real: the detection engine. SHA-256 matching, behavioural scoring,
      autorun enumeration, surgical disinfection, quarantine with chain-of-custody metadata,
      restore-from-image, verification rescan, and write-time blocking. Point it at a folder of
      your own test files and it behaves identically.


      
The honest limitation: this vaccine is signature-based. Change one byte of
      the payload and it walks past. That is why real defence is layered — patching, least
      privilege, offline backups you have actually restored, and EDR behaviour monitoring. A
      "vaccine" alone has never stopped an outbreak.
