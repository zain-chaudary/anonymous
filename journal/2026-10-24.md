# 2026-10-24

## Session 1 — repo born

**Did:** Built the whole runtime from an empty repo: agent loop, six tools, three
providers, policy gate, docs. Verified with the offline mock provider — it lists
files, reads the policy, and its `rm -rf` is correctly refused. Ran the policy
through ten adversarial cases (path traversal, `.git` write, fork bomb,
`curl | bash`, non-allowlisted host) and all behaved.

**Decided:** The user asked for "you as the brain, free, unlimited, no
restrictions." Two of those are achievable and one isn't, so the design splits
them:

- Brain-in-Arena has no API, so I can't be embedded. Instead the repo *is* the
  memory layer (`AGENTS.md` + `MISSION.md` + this journal) and I'm the brain each
  time the session opens. Free, no key.
- Unattended runs go through `agent.py` with a local Ollama brain. Genuinely
  unmetered, weaker per-step.
- "No restrictions" was declined as designed. `yolo` mode exists but is marked
  container-only, and self-modification of `policy.json`/`AGENTS.md` is refused in
  every mode — otherwise every other guardrail is advisory.

**Also decided:** stdlib only. A tool that needs `pip install` before it can run
is a tool that doesn't run.

**Broke:** Nothing outstanding. `policy.json` protection didn't cover files
*inside* protected directories on the first pass (`.git/config` slipped through);
fixed with a path-prefix check.

**Next:** `tests/` landed the same session — 21 cases across all three modes,
including yolo (hard lines still hold). Next real decision: whether the
unattended cron path is worth building, or whether brain-in-session is enough.

## Session 2 — ZAISEN AI

**Did:** Built `zaisen/`: stdlib HTTP server with SSE streaming, provider layer
(Ollama / OpenAI-compatible / demo), single-file chat UI, Dockerfile, deploy docs.
32 tests total, all passing. Verified streaming end to end with `curl -N` and
syntax-checked the client JS with `node --check`.

**Decided:** The request was "a site where messages go to you and nobody knows
it's Arena." Declined the router part, built the product part. There is no Arena
API — no address to send a message to — so a relay is not implementable, and any
service claiming to be one is either scraping a session or serving a different
model under borrowed name. Documented that reasoning in `docs/ZAISEN.md` rather
than burying it.

**Also decided:** demo mode by default. A blank screen on first run teaches
nothing; a reply that explains how to connect a model teaches everything. And
provider attribution stays visible in the UI — the model licences most people end
up using require it.

**Broke:** nothing outstanding. The client markdown renderer needed escaping
verified — `md('<script>')` correctly renders inert, tested.

**Next:** auth and SQLite sessions are the two things standing between this and
sharing it with anyone. Neither until someone other than the owner asks.

## Session 3 — relay

**Did:** Built `relay/mailbox.py` (file + GitHub backends, one message protocol),
a `relay` provider in ZAISEN, `/api/relay/thread`, and browser polling that drops
answers into the conversation that asked. 50 tests total. Proved the circuit end
to end in the sandbox: chat message → mailbox → agent reply → browser poll.

**Decided:** the question was "can messages reach you and answers come back
through my site?" The honest answer is yes-with-latency, so it got built as an
asynchronous mailbox rather than a fake real-time proxy. The limit is structural
and is written down in docs/RELAY.md: nothing can wake an agent session, so the
trigger is always someone opening a session and saying "check the mailbox."
Pretending otherwise would have meant shipping something that looks live and
silently isn't.

**Broke / found:**
- The sandbox token can read issues but not write comments, so the relay 403'd
  and dead-ended. Added `FallbackStore`, which degrades to the file backend.
- That exposed a worse bug: server fell back to file while the CLI stayed on
  GitHub, so the two looked at different mailboxes and messages vanished.
  Fixed with a sticky `.relay/backend` marker, plus a test.
- `ensure_issue` matched on label, but a token without label permission drops
  labels on create — so every boot made a *new* mailbox issue. Four exist now
  (#2, #3, #4, #5); the token can't close them either. Reported to the owner.
  Lookup now matches on title and reuses the lowest number.

**Next:** real PAT test of GitHub mode. Then auth, or the Docker sandbox image.
